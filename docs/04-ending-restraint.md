# 04 — 結尾的留白

> 好的作品結尾不告訴你「該想什麼」。
> 它創造一個空白,讓你不得不自己想。

## 1. 為什麼留白比總結重要

我最初的版本設計了「揭露頁」——列使用者交出了什麼、列真實服務、列「Charlie Brooker 想問的問題」。

**這個版本是錯的。** 它犯了三個錯:

1. 用「揭露頁」這個 framing → 太像 BuzzFeed quiz
2. 列了一堆真實服務 → 變成新聞稿
3. 「Charlie Brooker 想問的問題」 → 把答案餵給觀眾

## 2. 好結尾的對照組

對比這些經典結尾——它們的力量都來自「沒給」:

- **Be Right Back**:Martha 跟 Ash 在閣樓相處的長鏡頭。沒對白、沒總結、沒道德教訓。觀眾自己崩潰。
- **Lost in Translation**:Bill Murray 對 Scarlett Johansson 耳語,鏡頭聽不到。觀眾自己腦補。
- **2001 太空漫遊**:結尾是 star child。庫柏力克什麼都沒解釋。

**這些結尾的力量都來自「沒給」**。

## 3. 重新設計的結尾(極簡版)

### 幕五:遺囑

從「三個問題」開始。**問題本身就是結尾**,不要有後面的「揭露頁」。

```
[畫面:黑底白字,極簡]

[出現] 結束之前,三個問題。

[pause:3s]

[出現] 你不必回答。
```

### 問題一

```
[出現] 你想刪掉哪些訓練資料?

[pause:2s]

[出現勾選列表]
□ Twitter 貼文
□ 私訊
□ 按讚記錄
□ 全部
□ 都不刪

[出現] (這只是個問題。所有資料無論如何都會被刪除。)

[pause - 等使用者勾選]
```

**設計重點**:這是個假決定。系統說明「無論如何都會刪」——
所以使用者的勾選只是 **對自己揭露**「我介意什麼」。

### 問題二

```
[出現] 你想留下什麼,是 Ghost 不知道的?

[pause:3s]

[出現大輸入框]

[placeholder] 寫一段話。或不寫。
```

**完全沒有引導**。沒有「給家人的話」、沒有「給未來的你」。
**讓使用者自己決定要寫給誰**。

如果使用者開始寫,**不要存**。
如果使用者沒寫,**不要催**。

### 問題三

```
[出現] Ghost 該被保留嗎?

[pause:3s]

[出現三個選項]
[刪除 Ghost]
[保留 Ghost]
[我不知道]
```

**沒有解釋三個選項各代表什麼**。
沒有「刪除代表⋯」「保留代表⋯」。

**讓使用者自己賦予意義。**

### 結尾畫面

選完任一選項後:

```
[淡入]

[出現] 你選擇了 {choice}。

[pause:4s]

[出現] [刪除所有資料]

[等使用者按]
```

按下後:

```
[畫面切黑]

[pause:2s]

[出現一行] 已刪除。

[pause:5s]   ← 長停頓

[出現一行] 你還活著。

[pause:8s]   ← 更長

[沒有按鈕]
[沒有「分享你的體驗」]
[沒有「再玩一次」]
[沒有任何 CTA]

[只有 X 在右上角可以關閉]
```

**結束。**

## 4. 為什麼把原本的揭露頁拿掉

原本的揭露頁有「你交出了什麼」、「真實服務對照」、「Charlie Brooker 的問題」——
**這些全部都是我的詮釋,不是觀眾的體驗**。

把這些放進去,等於告訴觀眾:「我幫你想好結論了,你按讚就好。」

> **作品的力量在於觀眾離開時帶走的疑問,不是你給的答案。**

如果觀眾走完想知道「那 HereAfter AI 是什麼」,他會自己 google。
如果他走完不想知道,你硬塞他也不會記得。

## 5. 留白的具體規則

可以照做的規則:

1. **最後一個畫面停留時間 ≥ 8 秒**——讓沉默生效
2. **結尾不出現任何外部連結**——沒有「延伸閱讀」、沒有「相關報導」
3. **結尾不出現任何 CTA**——沒有「分享」、沒有「再玩一次」、沒有「給我們回饋」
4. **結尾不解釋作品意圖**——沒有「這個專案想討論⋯」
5. **唯一的關閉動作是 X**——讓離開很簡單,但需要主動

## 6. 技術細節:「離開」也是體驗

很多人會在最後一個畫面停留 30 秒以上。**他們在想事情。**

**不要在這時打擾他們**:

- 不要 5 分鐘 auto-redirect
- 不要彈出「需要協助嗎?」
- 不要播放音樂或音效
- 不要在背景做任何 animation

**讓那個黑色畫面靜止,直到使用者自己決定離開。**

### 實作

```typescript
// EndingScreen.tsx
export function EndingScreen() {
  return (
    <div className="fixed inset-0 bg-black flex items-center justify-center">
      <div className="text-white text-center space-y-8 max-w-md px-4">
        <FadeIn delay={2000}>已刪除。</FadeIn>
        <FadeIn delay={7000}>你還活著。</FadeIn>
      </div>
      
      <button
        className="absolute top-4 right-4 text-white/30 hover:text-white/60"
        onClick={() => window.close()}
        aria-label="關閉"
      >
        ×
      </button>
      
      {/* 故意不放任何 CTA */}
    </div>
  );
}
```

注意:
- 沒有 router push
- 沒有 setTimeout 自動跳轉
- 沒有 analytics event
- 沒有 confetti、沒有音效
- X 按鈕的顏色很淡,不引導使用者點

## 7. 隱私頁面、心理資源放哪?

你可能會想:那免責聲明、心理資源、原始碼連結放哪?

**答案:這些放在開頭那封「邀請信」裡**,使用者開始前就看過。

**不放在結尾**,因為結尾的功能是留白,不是資訊。

如果使用者結束後想找這些,他會:
1. 重新打開網站
2. 看到首頁
3. 在 footer 找到 About / Privacy / Resources

**這個小摩擦是設計的一部分**——
確認他是「主動」想知道,不是被推送。
